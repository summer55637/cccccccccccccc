# 暴露憑證輪替清單

本清單依 2026-11-07 對私有倉庫的唯讀盤點整理。不要把任何新密碼、Token、Cookie、金鑰或完整設定檔貼到聊天、Issue、Pull Request 或 Git。

## 1. 先限制暴露面

- [ ] 保持 GitHub 倉庫為 Private，檢查協作者名單並移除不再需要的人員。
- [ ] 不要部署 `main`、`backup/pre-security-cleanup-2026-11-06` 或任何含舊版伺服器檔案的分支。
- [ ] 若舊伺服器仍對外提供服務，先限制外部存取或暫停敏感端點；不要在未完成替代方案前直接刪除正在使用的資料。
- [ ] 保留必要的安全事件紀錄，但避免將含有 Token 的原始日誌再次上傳。

## 2. 帳戶密碼

原始 `local_accounts.json` 含 12 筆帳戶紀錄，欄位包含 `username`、`password` 等資料。應把這些密碼全部視為已暴露。

- [ ] 在帳戶所屬服務端，逐一重設這 12 筆帳戶的密碼；每個帳戶使用不同且唯一的新密碼。
- [ ] 若任何舊密碼曾在其他網站或服務重複使用，也要在那些服務分別更換。
- [ ] 能強制登出所有裝置時，執行強制登出。
- [ ] 驗證舊密碼已不能登入；不要只刪除本機 JSON 檔就視為完成。

## 3. 工作階段與 Token

原始檔案另含 32 個 Token 值。應把它們全部視為已暴露。

- [ ] 在 Token 的簽發服務端撤銷或刪除全部舊 Token／工作階段。
- [ ] 若服務使用 Token 簽章密鑰，評估輪替簽章密鑰並使舊 Token 全部失效。
- [ ] 驗證舊 Token 無法再存取 API 或建立 WebSocket 連線。
- [ ] 確認伺服器日誌、除錯輸出及錯誤追蹤不會記錄完整 Token。

## 4. 伺服器硬編碼金鑰與端點

目前各分支的 `server.js` 內容相同，仍有硬編碼的封包加密金鑰，以及與 Token 包裝、Token 記錄、CORS 和 WebSocket 身分回退有關的風險。

- [ ] 將硬編碼金鑰視為已暴露。先釐清它保護哪些封包、客戶端如何取得，以及輪替時是否需要重新加密或遷移資料。
- [ ] 在安全的伺服器設定／秘密管理服務中建立新金鑰；不要把新金鑰放入前端程式、Git 或聊天。
- [ ] 移除或改造可由呼叫者自行提供 Token、但未在服務端驗證權限的金鑰包裝端點。
- [ ] 將 CORS 改成明確允許清單。
- [ ] WebSocket 驗證失敗時必須拒絕連線，不可使用 Token 衍生的預設身分。
- [ ] 以測試確認舊金鑰、舊 Token、無效 Token 和未授權來源均遭拒絕。

注意：不要只替換硬編碼金鑰字串就直接上線；若現有資料仍以舊金鑰加密，必須先設計並測試重新加密／遷移流程。

## 5. Git 歷史處理

- [ ] 先確認帳戶密碼、Token 及伺服器金鑰已在簽發端撤銷或輪替。
- [ ] 決定是否需要保留原始備份；若要保留，應另存於加密、受限存取的離線位置。
- [ ] 規劃跨所有分支、標籤及其他 Git refs 的歷史重寫；只刪除最新檔案不會清除舊提交中的內容。
- [ ] 歷史重寫前盤點協作者、複本、Fork 與 CI 快取；完成後要求使用者重新 Clone，不要把舊歷史推回遠端。
- [ ] 目前 `main` 與原始備份分支仍指向含敏感檔案的初始提交。依目前工作限制，`main` 尚未修改；任何改寫 `main` 或刪除備份分支的動作都必須先取得明確授權。

## 6. 完成驗證

- [ ] 在所有現存分支、標籤、Git 歷史及部署產物執行完整秘密掃描。
- [ ] 確認舊密碼、舊 Token 及舊金鑰確實失效。
- [ ] 確認新的憑證只存在於服務端秘密管理系統。
- [ ] 確認公開部署只包含已授權的單機版檔案，不包含原始帳戶資料、舊伺服器或未確認授權的遊戲素材。

## 尚未代辦的項目

這份清單不代表已完成外部密碼重設、Token 撤銷、金鑰輪替或 Git 歷史重寫。這些動作必須在各憑證簽發服務及 GitHub 設定中執行，並逐項驗證。
