# 原始 Cocos 客戶端單機化重建設計

日期：2026-11-08
狀態：依使用者已選定的單機化方向執行；使用者表示已取得修改及公開發布授權。

## 目的

把目前由爬取資料保存下來的「小樹」原始 Cocos Creator 3.8.8 客戶端，改造成可由 GitHub Pages 免費託管、在瀏覽器內單人遊玩的版本。遊戲畫面、地圖、角色、怪物、動畫、道具與原始玩法以現有客戶端和資料為基礎；不再以目前的簡化自製地圖原型冒充原遊戲。

## 已確認的現況

- 原始入口在 `client/index.html`，啟動 Cocos Creator 3.8.8；遊戲主 bundle 約 6 MB。
- `client/` 目前有約 1,185 個檔案、約 287 MB，包含 Cocos runtime、主 bundle、資源 bundle、地圖／圖像資源包和 PWA 檔案。
- `extracted_data/gamedata.json` 約 368 KB，包含 93 張地圖、248 種怪物、665 件道具、123 個技能、11 個城鎮、53 個娃娃與 22 個世界首領資料。
- `tools/goline.proto` 定義完整客戶端訊息格式；包含角色、狀態、地圖實體、移動、戰鬥、道具、技能、NPC、任務、倉庫等訊息。
- 現有 `server.js` 不是完整遊戲伺服器。它只實作簡易註冊／登入、創角、選角、進地圖、移動及聊天回應；沒有實作怪物生成、攻擊結果、掉落、技能、商店、NPC、任務、背包等核心遊戲邏輯。
- 現有 GitHub Pages 發布包只包含 `offline/` 下的簡化原型，刻意排除了原始 Cocos 客戶端，因此目前網站與原遊戲不同。
- `client/src/assets/scripts/net/goline-adapter.deobf.js` 提供 `window.GolineSocket`，其事件層可作為本機服務層的相容接點；其內部仍使用 WebSocket／Protobuf 傳輸。

## 方案比較

1. **原始 Cocos 客戶端 + 瀏覽器本機遊戲服務層（採用）**：保留原遊戲畫面與素材，以瀏覽器內的本機服務層取代遠端 WebSocket 伺服器，角色與世界狀態寫入 IndexedDB。GitHub Pages 只需託管靜態檔案；適合已決定的單機方向。代價是必須補齊遊戲伺服器原本負責的玩法邏輯。
2. **原始 Cocos 客戶端 + 外部 Node.js 伺服器**：較接近線上架構，但 GitHub Pages 不能執行 Node／WebSocket 伺服器；還要額外部署和維護後端。現有 `server.js` 只是 stub，不能直接提供完整玩法。
3. **重新製作另一套 HTML 遊戲畫面**：可以獨立控制，但必須重做原始畫面、地圖、動畫和介面，正是目前原型失敗的原因，不採用。

## 採用方案的設計

### 靜態遊戲殼層

- 將原始 `client/` 內容以原本相對路徑部署到 Pages 網站根目錄，讓 Cocos 的 SystemJS、bundle、PWA、資源包 URL 保持一致。
- 將必要的 `extracted_data/*.json` 放入公開成品的資料目錄，並由本機 API 相容層提供原客戶端讀取。
- 在 Cocos plugin 載入後掛接本機 Goline 服務層，阻止連到原伺服器；不可把 `server.js`、`local_accounts.json`、`node_modules`、測試帳密或伺服器金鑰放入 Pages 成品。
- GitHub Pages 只作靜態託管；瀏覽器端負責所有本機遊戲邏輯與資料保存。

### 本機遊戲服務層

- 提供與原始客戶端相容的登入／角色事件，但不要求線上帳號；每個瀏覽器使用自己的 IndexedDB 存檔。
- 對外保留原本 `GolineSocket` 事件介面，將客戶端發出的動作送往瀏覽器本機遊戲服務層，再以原客戶端預期的事件資料格式回傳。
- 用 `gamedata.json` 作為地圖、怪物、道具、技能、城鎮與系統定義的主要資料來源。
- 逐步實作角色狀態、地圖實體、怪物 AI、移動、攻擊、傷害、死亡／重生、經驗、升級、掉落、背包、裝備、技能、NPC、商店及任務。
- 重要狀態在每個遊戲動作後原子保存；支援匯出／匯入備份與離線重新開啟。

### 範圍

目標是單人遊玩。多人同圖、即時聊天、玩家交易／市場、跨裝置同步、付費與原線上伺服器服務不列入第一階段。可依現有資料逐步實作單人可用的替代流程。

## 安全與相容性限制

- 只在 `offline/local-character-system` 分支工作，不修改 `main`。
- Pages 封裝採明確 allowlist；不複製伺服器、帳號資料、Token、Cookie、金鑰、node_modules 或備份。
- 既有公開倉庫與 Git 歷史中曾出現的憑證仍須視為已暴露；此次遊戲封裝不會帶入這些檔案，也不代表已完成憑證輪替。
- Cocos bundle 與資源包總量約 287 MB，需驗證 Pages 封裝大小、所有相對路徑、資源載入和快取容量。
- 若原始客戶端依賴未擷取的伺服器資料或資源，必須明確列為缺口，不以假回應宣稱完成。

## 驗收條件

1. Pages 首頁直接啟動原始 Cocos 角色／登入流程，不再顯示簡化原型。
2. 不需外部伺服器即可建立、選擇及保存本機角色。
3. 可在原始遊戲地圖移動，看到原始地圖與遊戲實體。
4. 可完成基本攻擊、怪物死亡、經驗／升級及掉落，並保存重整後的狀態。
5. 背包、裝備、基本技能及 NPC 核心互動有相應的本機流程。
6. 首次載入後能由 Service Worker 快取必要資源；重新開啟可使用本機存檔。
7. CI 驗證封裝 allowlist、資源完整性、遊戲服務單元測試和 Chromium 瀏覽器流程；未通過者不發布。
